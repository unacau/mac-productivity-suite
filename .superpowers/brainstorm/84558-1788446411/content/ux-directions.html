Browser Profile UX & Selection Architecture

Select the UX direction that best solves the profile mismatch and improves workflow clarity.

A

Dedicated "Browser Profiles" Tab & Manual Mapping

A new Settings tab that displays all discovered profiles with their real avatars, emails, and live menu positions. Lets users customize shortcut keys directly (e.g., Hyper + 1, Hyper + 2) and includes an interactive "Test Focus" button to immediately verify window switching.

Pros

  • 100% deterministic: user sees exact mapping
  • Easy to test & debug profile switching on any machine
  • Custom hotkey assignment per profile

Cons

  • Requires initial one-time configuration if automatic order doesn't match preferences
B

Smart Dynamic Menu Synchronization (Zero-Config)

Automatically synchronize with the live Chrome menu bar. Instead of showing internal directory IDs like Profile 2, the switcher and Settings dynamically display Chrome's formatted names (e.g. Igor (Al11)) and bind Hyper + 1..9 directly to the exact live menu bar positions.

Pros

  • Zero configuration needed
  • Always mirrors Chrome's real menu order (1st item = 1, 2nd = 2)
  • Works seamlessly across multiple Macs without manual setup

Cons

  • Menu order is controlled by Chrome's sorting algorithms
C

Unified App & Profile Carousel with Instant Visual Badging

Treat profiles as first-class applications in the App Switcher HUD. Show rich circular profile badges with account emails and active indicators, and allow switching between profiles using normal App Switcher key cycling or numeric direct-jump.

Pros

  • Deeply integrated with the existing app switcher workflow
  • Clear visual distinction between work and personal profiles

Cons

  • Still requires underlying menu synchronization to be solved accurately
